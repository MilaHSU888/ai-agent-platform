## 1. 產品目的與成功條件

WorkHub 整合公司分散的工具，提供統一入口、權限、部署、模型接入及使用分析。平台不預測未來有哪些工具，也不以現有清單、業務類型、開發語言或固定數量限制上架；符合工具上架標準並通過接入驗證的工具，可由客戶 AI 團隊持續上架。

本期完成平台、1–2 個工具試點與技術移轉，另行建置 AI 識圖。使用 LLM 的工具可由後台切換相容且核准的地端／雲端模型；模型切換遵守資料政策，不代表各模型輸出品質相同。

### 1.1 名詞定義

| 名詞 | 定義 |
| :---- | :---- |
| **有效入口點擊** | 使用者在 WorkHub 內點選工具入口，且通過平台權限檢查與入口狀態檢查後所記錄的一次點擊。工具後續是否成功開啟、是否完成工作，均不影響該筆紀錄。書籤、直接輸入工具 URL 或其他外部入口無法記錄，不納入點擊統計與主管分析。權限或入口狀態阻擋另留事件紀錄，不計為有效入口點擊。同次紀錄重送不重複計數。 |
| **AI 工具／非 AI 工具** | 依工具是否經 LLM Proxy 呼叫模型區分。兩者的有效入口點擊皆由 WorkHub 後端記錄；AI 工具另由 LLM Proxy 記錄模型呼叫與 Token 用量，兩份資料分開統計。 |

本文件後續章節提及入口點擊時，均指本表定義之「有效入口點擊」。

### 1.2 成功條件

| 成功條件 | 驗收／量測方式 |
| :---- | :---- |
| 授權正確 | UAT 無越權案例；平台與工具端均驗證權限 |
| 試點全流程完成 | 雙方選定的 1–2 個工具完成上架、使用、更新及回復；AI 識圖不計入 |
| 自主管理與技術移轉 | 客戶依文件完成新工具上架及設定，不需修改平台程式 |
| 工具入口點擊紀錄 | 可在管理後台查看有效入口點擊的紀錄與次數；平台不判定工具是否成功啟動或完成工作 |

### 1.3 AI 識圖辨識率的承諾界線

AI 識圖的辨識欄位、標準答案、測試集、計算公式與通過門檻依 TBD-VIS-001 由品保核准。**門檻核准前，本 PRD 不構成任何辨識準確率承諾**；P1-VIS-015 要求的是在核准測試集上完成量測並保存可複核的成功率報告，而非達成特定數值。

若首次量測結果未達核准門檻，處理方式（調整模型或推論參數、縮限辨識欄位範圍、改以人工為主 AI 輔助、或調整門檻）由雙方於量測報告產出後另行議定，並依現行時數合約計算後續投入。

## 3. 角色、使用流程與介面

### 3.1 角色與主要流程

| 角色 | 主要操作與責任 |
| :---- | :---- |
| 一般員工 | 使用獲授權工具、申請權限、回報問題 |
| 品檢員 | 執行 AI 識圖、校對、確認與匯出 |
| 主管 | 查看授權範圍的使用與效益彙總，不查看員工完整 Prompt／附件／回應 |
| 客戶 AI 團隊／平台管理員 | 管理工具與模型設定、最終授權、上下架與平台問題 |
| 內部開發者／工具 Owner | 提交與修正工具、更新資料、處理內容問題及生命週期 |
| IT／資安 | 身分與設備、資料政策、備份與資安窗口；依職責授權 |

* 員工：公司身分登入 → 搜尋／找工具 → 必要時申請權限 → 使用 → 回報問題。未授權工具的功能與資料保持封鎖；是否顯示可申請的公開工具摘要待 UI 規格確認。

* 工具接入：WorkHub 後端記錄有效入口點擊並傳遞可信身分 → 工具驗證後免重複登入；使用 LLM 時，模型呼叫另經 LLM Proxy 記錄。平台不追蹤一般工具的啟動或工作完成結果。

* AI 識圖：上傳檢查 → 地端辨識 → 圖面定位及人工修正 → 整體確認 → Excel 匯出，原始值與修正值分開保存。

* 工具管理：依第 5 章上架及更新；平台授權與工具端驗證共同生效。

### 3.2 一般工具流程

**流程步驟**

1. 使用者 → AD／SSO 登入

2. → WorkHub 顯示獲授權工具

3. → 權限與入口狀態檢查

   * 不通過 → 阻擋並記錄事件（不計入點擊）

   * 通過 → **記錄有效入口點擊** → 啟動既有工具

4. 工具是否使用 LLM？

   * 是 → LLM Proxy → 模型呼叫與 Token 紀錄

   * 否 → 平台不再追蹤執行結果

5. 有效入口點擊紀錄 ＋ 模型呼叫紀錄 → 統一分析儀表板

圖示重點：**所有工具**（含使用 LLM 者）皆於通過檢查後記錄一次有效入口點擊；使用 LLM 的工具另有一份 Proxy 模型紀錄，兩份資料分開統計後於分析頁彙總。

### 3.3 AI 識圖流程

**流程步驟**

1. 上傳工程圖

2. → 格式與檔案檢查

3. → 地端 5090 AI 辨識與定位

4. → 顯示單欄辨識結果

5. → 人工逐圖核對並修正錯誤

6. → 最終人工確認

7. → 依範本匯出 Excel

8. → 保存原始值、修正值與稽核紀錄

AI 識圖涵蓋基隆、汐止及越南廠區；使用者名單、介面語言與網路需求由客戶確認（TBD-NFR-004）。**跨廠區／跨境的圖面與推論資料傳輸**（含越南廠區上傳至台灣地端運算環境）之法遵、加密與落地要求，由客戶資安確認（TBD-VIS-003），未確認前不進行越南廠區實機接入。容量需求列於第 7 章待確認事項。

## 4. 功能與工具上架標準

### 4.1 工具上架標準

| 標準 | 最低要求 |
| :---- | :---- |
| 容器化交付 | Docker image 包含工具與仍受維護的執行環境，符合平台作業系統／架構；原始碼提交須附建置設定，平台自動建置 image |
| 瀏覽器操作 | 提供可透過 URL 使用的網頁服務 |
| 平台身分整合 | 接受並驗證平台身分，免重複登入，不以可偽造的前端參數授權 |
| 統一模型接入 | 使用 LLM 時統一經 LLM Proxy；模型憑證集中管理；非 LLM 工具不適用模型設定 |
| 資源與責任登錄 | 申告 CPU／記憶體／GPU、必要網路連線及 Owner；未申告連線預設禁止，資源依核准配置 |

任何符合五項標準並通過接入及安全檢查的工具均可上架。不要求所有工具共用語言或業務格式。排程服務保留擴充設計，非網頁及特殊依賴走例外評估，具體接入工作先確認。

**附件缺件影響（重要）**：健康檢查、事件介面、身分傳遞、儲存與建置資料等**技術契約細節，定義於〈02-事件與 LLM Proxy 規格〉附件**。該附件產出前，客戶 AI 團隊無法自行評估既有工具是否符合上架標準，TBD-PILOT-001 的試點選擇亦缺乏判斷依據。故該附件列為 PRD 確認後的**第一優先交付文件**。

| 修正與確認 | 開發者處理問題，指定審核者確認阻斷問題；AI 結果可漏報／誤報，不能單獨保證安全 |
| 測試 | 在獨立測試環境驗證功能、身分、模型、事件與更新相容性 |
| 發布 | 經核准流程部署正式環境，保留版本、設定與檢查證據 |
| 版本回復 | 驗證前一版本可運作；涉及資料庫／資料格式變更時包含相容性處理及必要還原 |

敏感資料或對外連線工具採完整流程；一般內部查詢工具可採核准的簡化流程，仍需自動 AI／必要漏洞檢查及發布管制。禁止直接上傳程式至正式環境。風險分級、檢查工具、發布確認人與阻斷標準見 TBD-RELEASE-001。

### 5.2 三種更新

* 說明、URL、權限與模型設定：後台修改生效並保留異動紀錄。

* 程式：依發布流程執行。

* 業務資料：Owner 由工具管理頁上傳，容器內處理與回報結果。共用上傳元件或接入範本形式待確認；工具特有轉檔、欄位映射與檢核由工具開發者接入。

### 5.3 上線順序

1. 試點：先以「採購報價單彙整工具」跑通提交、檢查、測試、上架、授權、使用、更新及回復，關閉阻斷問題。

2. 技術移轉：客戶 AI 團隊／內部開發者依文件親自完成第 6 章演練。

3. 後續上架與推廣：由客戶自行安排其他工具遷移，完成公告、教學與支援窗口交接。

AI 識圖另行安排地端模型測試、品保 UAT 與上線檢查，不以試點完成取代。只有 1 個試點時，平台 LLM／非 LLM 的必要接入分支仍以測試案例驗證，不自動增加代建工具範圍。

- 開發者中心可下載兩種資料包：**上架資料包**（首次上架；含 SOP、`workhub.yaml` 範本、離線預檢程式、給 AI agent 的打包指令）與**更新資料包**（從工具列下載；已預填該工具的 `tool.id`、下一個版本號與可用模型端點代號）。
- 開發者把資料包與程式碼交給 AI agent，即可產出一個可上傳的 ZIP；上傳前可用離線預檢，結果與平台收件檢查一致。
- 工具名稱、部門、Owner 在網站表單填寫（以平台為準）；`tool.id` 寫在 `workhub.yaml`，上架後不可改。

### 9.3 程式碼檢查（人工確認）

v0.18 §5.1 的「AI 檢查」改為**人工程式碼檢查**，由開發者自行檢查後按「已檢查」，不使用 AI，原始碼不會送到任何模型（DEC-019）。

| 項目 | 設計 |
|---|---|
| 流程位置 | 上傳 → 自動建置 → 漏洞檢查 → **程式碼檢查** → 開發者預覽與測試 → 提交發佈申請 |
| 觸發 | 漏洞檢查完成後，步驟顯示「待人工確認」，提交詳情出現程式碼檢查卡片與「已檢查」按鈕 |
| 開發者動作 | 檢查原始碼（寫死的帳密、對外連線、刪改資料的動作），按「已檢查」即代表通過，備註選填；有問題則「取消提交」，修正後重新上傳 |
| 管制 | 按「已檢查」前不能確認測試結果，也不能核准發布；檢查綁定該版原始碼雜湊與 image，上傳新版本或取消提交即失效；同一版不能重複按 |
| 紀錄 | 檢查者、時間、備註寫入確認紀錄與稽核紀錄；發布管理的審核卡片顯示誰在何時按了「已檢查」，供管理者核准時參考 |

程式碼檢查由開發者自己負責；發布前仍須管理者核准。正式環境是否另需與開發者不同的人複核，待客戶確認（併 TBD-RELEASE-001）。

### 9.4 偏離 v0.18、需客戶確認的差異

| 差異 | v0.18 原文 | 本機試點做法 | 影響與待確認 |
|---|---|---|---|
| 程式碼審查 | §5.1、P1-RELEASE-001：AI 程式碼檢查 | 開發者人工程式碼檢查，按「已檢查」即通過（9.3） | 若確認採用，§5.1「AI 檢查」與 TBD-DATA-001 中「AI 程式碼檢查用模型」可移除 |
| 漏洞處理 | P1-SEC-002、§5.1：阻斷問題需確認 | 只記錄、不阻擋；掃描器無法執行時才阻擋 | 正式是否需要阻斷標準（如 CRITICAL 須例外核准）併 TBD-RELEASE-001／TBD-SEC-001 |
| 工具資料來源 | P1-TOOL-001：後台登錄 | 名稱、部門、Owner 由上架表單填寫；名稱可在發布管理修改 | 與後台登錄一致，僅入口不同；請客戶確認 |

### 9.5 本機試點未涵蓋

AD／SSO 與部門權限；平台傳遞身分給工具（P1-TOOL-002）；LLM Proxy 的配額、雲端模型與資料政策；第二個工具的版更發布（CNC作業指導書 1.0.1 進行中）；多台主機與 amd64；AI 解析準確度（DEC-028：階段 D 只驗證能連到模型）。



## 10. 2026/10/19 既有網站 URL 上架與客戶網路設定補充

來源：Mila 要求開發者可設定 OpenWebUI、n8n 等既有網頁工具入口。以下為新增需求與待辦，尚未實作或驗收；不代表新增工具代建置或代維運的試點承諾。

### 10.1 既有網站 URL 上架

- 開發者中心「新增工具」提供兩種接入方式：「上傳原始碼 ZIP（平台託管）」與「登錄既有網站 URL」。對應 P1-TOOL-001/006/008、P1-ADMIN-001、P1-PORTAL-004/005/006/008、P1-AUTH-006/007。
- URL 表單登錄名稱、用途、分類、部門、Owner、入口 URL、操作說明、資料限制、登入／身分整合方式、申請使用角色及是否使用 LLM。開發者提出權限需求，由管理者核准，不能自行擴大授權。
- 流程：填寫 → 欄位與核准網路範圍檢查 → 入口及身分／權限測試 → 管理者核准 → 建立 WorkHub 入口。URL 模式不要求 ZIP、Dockerfile 或 image 建置，不將不適用的建置／程式碼檢查標為已通過。
- 支援修改入口、重新送審、維護、下架及設定歷程；核准綁定送審設定，修改後須重新確認。回復僅涵蓋平台入口設定，不宣稱能回復外部網站程式或資料。
- WorkHub 後端檢查使用權限及入口狀態並記錄有效入口點擊；外部網站須有自己的可信登入與授權整合，只有隱藏入口不能阻擋直接 URL 存取。無法符合身分接入標準者先列待處理，不當作完成正式接入。
- n8n 登錄供使用者操作的網頁／表單入口；不直接把會觸發工作執行的 webhook 當成連線測試目標。確切工具名稱、URL、登入方式及測試入口由 Owner 提供。
- 後端 URL 檢查依 IT 核准的主機、網段及重新導向政策執行，避免任意探測內網；內部網站可用，但不得自行假定所有內網位址均可存取。
- 使用 LLM 的既有網站仍須核對模型資料流與核准政策；登錄 URL 本身不會自動將外部網站改接 LLM Proxy。

### 10.2 客戶 Proxy：部署前確認、部署時套用

- 客戶所稱 Proxy 尚須釐清種類，不把企業出網 Proxy、網站反向代理與 LLM Proxy 當成同一設定。
- 企業出網 Proxy：IT 提供位址、埠、驗證方式、企業 CA、可連線目的地及不經代理的內網範圍；在環境準備階段確認，建置與部署時套用。涵蓋套件／image 下載、漏洞資料更新及核准雲端連線；不得讓所有工具因此取得任意出網權限。
- 網站反向代理：在正式部署設計確認網域、HTTPS、轉送路徑及 WebSocket；部署驗證時核對工具入口與身分傳遞。
- LLM Proxy：屬於平台模型管理功能，須在模型串接開發／整合測試時完成路由、權限、配額及用量紀錄，部署時設定客戶實際端點。既有本機轉接不等於正式全部功能完成。
- 密碼與金鑰經安全設定管理，不寫入 ZIP、URL、原始碼或一般日誌。連線及信任政策依 TBD-AUTH-001、TBD-LLM-001、TBD-RELEASE-001、TBD-DATA-001、TBD-SEC-001 確認，不自行關閉。

### 10.3 驗收與交付

- URL 上架：合法入口可送審，缺欄位可補正；未授權提交／核准／開啟被拒絕；停用、錯誤 URL、重新導向及身分失效有正確處理；更新設定後舊核准失效；不執行 Docker 建置或觸發 n8n 業務工作。
- Proxy：於客戶核准網路測試必要下載、內網直連、模型呼叫與失敗提示；未核准目的地仍被阻擋，憑證不出現在日誌。
- SOP 補充兩種上架方式、URL 工具設定範例、入口設定回復及外部服務維運責任；測試狀態：未執行（需求補充）。
