# Phase 1 使用事件與 LLM Proxy 規格

## 1. 共用識別

AI 與非 AI 資料至少以以下識別關聯：

| 欄位 | 用途 |
|---|---|
| `event_id` | 單一事件唯一識別，防止重複寫入 |
| `run_id` | 一次工具執行或工作流程識別 |
| `tool_id` | 工具目錄中的穩定識別 |
| `user_id` | 經核准處理的穩定使用者識別，不使用顯示名稱作主鍵 |
| `department_id` | 事件發生當下的授權部門 |
| `occurred_at` | 含時區的事件時間 |
| `event_type` | `started`、`completed`、`failed`；需要時另定義取消或階段事件 |
| `result` | 成功、失敗、取消或待處理等結果 |
| `error_code` | 可統計且不暴露敏感內容的錯誤代碼 |
| `duration_ms` | 適用事件的處理時間 |

正式命名、格式、必填及版本策略待技術設計確認；不得以自由文字錯誤取代可統計代碼。

## 2. 非 AI 工具事件

- 啟動：使用者已通過權限並實際進入工具。
- 完成：工具完成一個已定義的有效工作，不以單純開頁面計算。
- 失敗：工具開始後因系統或業務錯誤未完成。
- 重複送出相同 `event_id` 不得重複計數。
- 未收到完成事件的工作不得自動視為成功；逾時呈現方式待定。

## 3. LLM Proxy 紀錄

除共用識別外，至少評估保存：

- 模型及模型供應來源。
- 地端／雲端路由結果。
- 輸入、輸出及合計 Token。
- 排隊、首字與總回應時間（依 Proxy 能力）。
- 配額與政策判斷結果。
- 重試次數及最終錯誤代碼。
- Prompt、附件與輸出是否保存的旗標。

Prompt、附件、輸出全文及可還原個人的欄位，必須在資安確認後才可保存；主管分析預設不使用全文。

## 4. 路由與故障原則

依 P1-LLM-007，客戶 AI 團隊在後台逐工具設定核准模型端點、版本及配額；模型與端點不得寫死於工具。新建 Gateway 統一處理模型憑證與路由，相容模型間切換不需修改工具程式。設定操作須授權並留存異動紀錄；政策禁止或能力不相容時拒絕切換。非 LLM 工具不需模型設定，AI 識圖現行地端 5090 規則持續適用。

1. 工具先標記資料分級及允許模型範圍。
2. Proxy 依工具、使用者、資料分級、配額及可用性決定模型。
3. 禁止上雲資料在地端不可用時應失敗或排隊，不得自動降級至未核准雲端。
4. 重試與備援必須保留相同或更嚴格政策。
5. 所有阻擋、切換與超額均建立可追溯事件。

## 5. 指標語意

| 指標 | 建議定義 | 待確認 |
|---|---|---|
| 活躍使用者 | 期間內至少一個有效 `started` 或 `completed` 的唯一使用者 | 是否以完成為準 |
| 執行次數 | 唯一 `run_id` 數 | 哪些工具行為構成一次執行 |
| 完成率 | 完成執行 ÷ 已開始執行 | 取消與逾時的分母處理 |
| AI 使用量 | 依模型與路由彙總 Token／請求 | 是否顯示成本 |
| 節省工時 | 基準人工時間－實際處理時間 | 基準取得與異常值規則 |

## 6. 隱私與留存

- 儀表板優先使用彙總資料。
- 個人層級資料只供必要維運、資安及問題追蹤。
- 保存期限、遮罩、加密、備份、刪除與存取稽核待 IT／資安核准。
- 測試資料不得混入正式分析，正式與測試環境需可區分。
