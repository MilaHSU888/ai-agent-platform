# AI Agent Platform：企業智慧工具平台

本專案為企業 AI Agent 統一管理平台的 WorkHub 前端原型，用於呈現統一工具入口、部門權限、管理者儀表板、AI 識圖、企業／部門知識庫及 Prompt 等操作流程。

Proposal 仍分為兩個建置階段；目前前端以同一套導覽展示兩階段的介面概念，不代表所有後端、資料庫、AD、LLM Proxy、OpenWebUI 或既有工具串接均已完成。

## 平台原則

- Phase 1 先以 100 位使用者為導入基準，各部門安排代表使用者參與。
- 使用者透過 AD／SSO 登入後，只看到具備權限的工具。
- 介面維持簡單，登入後可直接進入工具，減少不必要的中間頁面。
- 各小工具保留既有 UI、Backend 及操作流程；平台負責入口、權限、發布治理及使用紀錄。
- AI 工具的 LLM 連線改經 LLM Proxy；非 AI 工具則寫入獨立的使用紀錄資料庫。
- AI 與非 AI 紀錄由統一分析服務彙整，供主管查看採用率、使用量及效益。
- 一般使用者僅透過問答使用獲授權的知識；知識庫內容與管理功能只對管理者顯示。

## 分階段範圍

| 階段 | 期間 | 主要內容 |
|---|---|---|
| Phase 1 | 1.5 個月 | 100 位先行使用者、AD／SSO、統一入口、既有工具整合、LLM Proxy、非 AI 紀錄、主管儀表板、AI Review 與 IT 部署流程 |
| Phase 2 | 1.5 個月 | 完整 Code Review、全公司／部門知識庫、OpenWebUI API、Prompt／Skill／MCP、進階分析及知識應用 |

兩個階段均包含開發、測試、UAT、教育訓練及正式上線。

## 部門分類

- 全公司共用
- 財務部、資訊部、人力資源部、總務部
- 研發部、採購部、業務部、資材部
- 製造一部、製造二部、經營管理室

正式分類及角色權限需再與公司 AD 組織及群組設定對應。

## 主要功能

### WorkHub 工具中心

- 依部門及 AI／非 AI 類型篩選工具
- 工具名稱與用途搜尋
- 只顯示目前使用者具備權限的工具
- 登入後可直接開啟工具，避免額外的啟動摘要或中間頁面
- 各工具保留原本的操作介面與工作流程
- 響應式桌面與手機版面

### 管理者儀表板

- 活躍使用者與整體採用率
- 工具執行次數與預估節省工時
- 部門使用排名與工具成效明細
- 本月、近三個月及本年度期間切換
- 正式上線後只呈現必要的彙總與效益資料，不讓主管查看員工的完整提問內容

### AI 識圖大師

- 使用客戶提供的真實球標辨識報告案例
- 中央圖面與右側辨識結果同步定位
- 選取項目時框選正確的圖面位置
- 使用者修改錯誤項目或標記問題，不要求逐筆點選「正確」
- 一張圖可能包含約 50 個檢查項目，操作設計以降低重複確認為原則
- 若採「預設正確、僅修改錯誤」，仍需提供最終人工覆核提醒或確認機制
- 保留原始值、人工修改、版本及操作紀錄，以支援追溯
- 人工覆核完成後支援 Excel 匯出；正式欄位與格式由品保單位確認

### 採購報價匯整工具

採購報價匯整工具是客戶已完成的既有小工具，Phase 1 僅負責整合入口、權限及使用紀錄，不重新開發其原有 UI、Backend 或功能。

目前原型展示的操作包含：

- 採購案編號必填驗證
- 數量區間設定
- 多格式、多檔案拖放上傳
- 檔案清單、單筆移除與清空重來
- 比較表匯出狀態、使用說明及歷史查價

### 企業／部門知識庫

- 全公司及每個部門皆有知識庫問答入口
- 自動附加「全公司＋目前部門」知識庫
- 顯示引用來源與原始文件入口
- 部門專屬建議問題與對話紀錄
- 一般使用者只能問答及查看獲授權的引用來源，不直接查看或管理知識庫內容
- 部門管理員可新增知識庫、上傳文件及啟用／暫停來源
- 全公司必備來源由平台管理員控管

### Prompt 範本

- 個人、部門共用及全公司共用 Prompt
- Prompt 搜尋、一鍵套用與快速選擇
- 輸入 `/` 顯示可用 Prompt
- 輸入前幾個字即時縮小範圍
- 支援方向鍵、Enter、Tab 與 Esc 操作
- 目前原型以瀏覽器端保存進行展示；Phase 2 正式版本需改為伺服器端保存，確保重新登入後仍可使用
- 後續可延伸 Skill、MCP 及快查能力，並依角色限制可使用範圍

## 目前已知的整合情境

| 工具 | 主要用途 | 整合定位 |
|---|---|---|
| CRM 業務助理 | 查詢客戶、案件、機會及歷史互動 | 從統一入口開啟，保留原工具介面 |
| 歷史資料助理 | Email、報價、合約、PO／RFQ 及會議記錄歸戶 | 跨文件搜尋、時間軸及來源文件 |
| RFQ／PO 查詢助理 | 查詢 RFQ 與 PO 資料 | Phase 1 維持唯讀，不寫回 ERP |
| 採購報價匯整工具 | 匯整不同供應商及格式的報價資料 | 客戶既有工具，Phase 1 僅做入口、權限及紀錄整合 |
| 業務情報助理 | 整理市場、客戶、競品及新聞 | 保留來源及更新時間 |
| 會議／文件助理 | 整理會議記錄、交接摘要及拜訪紀錄 | 支援上傳、整理、人工修改及匯出 |

上述工具是否使用 LLM 需於正式整合前確認。使用 LLM 者接入 LLM Proxy；未使用 LLM 者接入非 AI 工具使用紀錄資料庫。

## 內部工具上架與審查

### Phase 1

內部開發者完成工具後，採用以下精簡流程：

`上傳 GitHub → AI Review → IT 審核、打包與部署 → 平台上架`

AI Review 的檢查項目及 IT 接手條件仍需定義。

### Phase 2

建立完整 Code Review 治理機制，包含：

- 人工審查及指定審查人。
- 程式品質、資安、權限與資料流檢查標準。
- 核准、退回修改及重新送審。
- 版本、發布及審查紀錄。
- 視開發者數量及治理需求，擴充開發者自助上架與管理後台。

## 平台資料流

### AI 工具

`AI 工具 Backend → LLM Proxy → 地端模型／核准的雲端模型`

LLM Proxy 負責資料政策、模型路由、Token、配額、回應時間及稽核紀錄。LLM Proxy 位於使用 LLM 的小工具與模型之間，不是與小工具平行的功能。

### 非 AI 工具

`非 AI 工具 → 統一使用事件介面 → 非 AI 工具使用紀錄資料庫`

### 統一分析

`LLM Proxy 紀錄＋非 AI 工具使用紀錄 → 統一分析服務 → 主管儀表板`

## 本機執行

### 系統需求

- Node.js `>=22.13.0`
- pnpm

### 安裝與啟動

```bash
pnpm install
pnpm dev -- --port 3002
```

開啟 [http://localhost:3002](http://localhost:3002)。`localhost` 僅供本機預覽，傳給其他人無法直接開啟；外部展示需另行部署或建立受控的分享網址。

### 建置驗證

```bash
pnpm build
```

## OpenWebUI 正式串接前置需求

目前 OpenWebUI 問答、Prompt 與知識庫管理為 Phase 2 前端展示。正式串接需要提供：

- OpenWebUI URL 與 API Token
- 使用模型 ID
- 全公司與各部門 Knowledge Base ID
- AD 群組與 OpenWebUI 權限對應
- Prompt 與知識庫管理 API 權限

正式上線時，使用紀錄應只保存必要的遙測與成效資料，不應讓主管查看員工的完整提問內容。
